- 20:45 ## 4. Java 객체지향 프로그래밍
- 20:45 ### 문제 41. Java의 상속
- 20:45 **문제:** 다음 중 Java의 상속(Inheritance)에 대한 설명으로 옳은 것은?
- 20:45 - 내가 선택한 답: ④ 부모 클래스의 생성자는 자식 클래스에 상속된다.
  - **정답: ③ `final`로 선언된 클래스는 다른 클래스가 상속할 수 없다.**
- 20:45 **오답 원인 및 개념 정리**
- 20:45 부모 클래스의 생성자도 자식 클래스에 상속된다고 잘못 이해하였다.
- 20:45 Java 상속의 주요 특징은 다음과 같다.
- 20:45 - Java 클래스는 다른 클래스 하나만 직접 상속할 수 있다.
  - 부모 클래스의 `private` 멤버는 자식 클래스에서 직접 접근할 수 없다.
  - `final` 클래스는 상속할 수 없다.
  - 부모 클래스의 생성자는 자식 클래스에 상속되지 않는다.
  - 자식 클래스의 생성자는 `super()`를 통해 부모 클래스의 생성자를 호출할 수 있다.
- 20:45 **기억할 점:** 생성자는 상속되지 않으며, `final` 클래스는 상속이 금지된다.

- 20:45 ## 6. JPA
- 20:45 ### 문제 78. JPA 변경 감지(Dirty Checking)
- 20:45 **문제:** `@Transactional` 환경에서 조회한 엔티티의 setter만 호출해도 UPDATE가 반영되는 JPA 기능은?
- 20:45 - 내가 선택한 답: ③ `Cascade`
  - **정답: ② `Dirty Checking` (변경 감지)**
- 20:45 **오답 원인 및 개념 정리**
- 20:45 JPA의 변경 감지 기능과 영속성 전이 기능을 혼동하였다.
- 20:45 **Dirty Checking**
- 20:45 - JPA 영속성 컨텍스트는 관리 중인 엔티티의 상태를 추적한다.
  - 엔티티의 값이 변경되면 변경 여부를 감지한다.
  - 트랜잭션의 flush 시점에 필요한 UPDATE SQL이 실행될 수 있다.
- 20:45 **Cascade**
- 20:45 - 엔티티 간의 관계에서 영속성 작업을 연관된 엔티티로 전파하는 기능이다.
  - 변경 감지 자체를 의미하는 기능은 아니다.
- 20:45 **기억할 점:** Dirty Checking은 엔티티의 변경 감지, Cascade는 영속성 작업의 전파이다.
- 20:45 ### 문제 79. JPA 기본키 생성 전략
- 20:45 **문제:** MariaDB/MySQL처럼 컬럼의 `auto_increment`로 PK를 생성하도록 하는 `@GeneratedValue` 전략은?
- 20:45 - 내가 선택한 답: ④ `GenerationType.AUTO`
  - **정답: ③ `GenerationType.IDENTITY`**
- 20:45 **오답 원인 및 개념 정리**
- 20:45 `AUTO`와 `IDENTITY`의 차이를 혼동하였다.
- 20:45 | 전략 | 의미 |
  |---|---|
  | `GenerationType.IDENTITY` | 데이터베이스의 자동 증가 컬럼 등을 활용 |
  | `GenerationType.AUTO` | JPA 구현체가 적절한 생성 전략을 선택 |
  | `GenerationType.SEQUENCE` | 데이터베이스 시퀀스를 활용 |
  | `GenerationType.TABLE` | 별도 테이블을 이용하여 키 생성 |
- 20:45 **기억할 점:** MySQL이나 MariaDB에서 `AUTO_INCREMENT`를 명시적으로 사용하는 전략은 `IDENTITY`이다.
