## 1. 웹 애플리케이션 동작 원리 (1-3강)

### 1.1 웹 개발 언어 및 개발 환경

**웹 개발 언어**

- Java: 상업용 웹 애플리케이션 개발
- Python: 데이터 분석, 시각화, AI 등에 활용

**IDE(Integrated Development Environment)**

통합 개발 환경을 의미하며, 코드를 작성하고 실행하는 데 필요한 기능을 제공한다.

- 코드 빌드(Build)
- 컴파일(Compile)
- 디버깅(Debugging)
- 콘솔 및 터미널 사용

**웹 서버 및 애플리케이션 서버**

- Nginx: 웹 서버
- Tomcat: Java 웹 애플리케이션 실행에 사용되는 서버 환경

### 1.2 HTTP Request(요청)

클라이언트가 서버에 데이터를 요청하거나 특정 작업을 수행하도록 요청하는 과정이다.

**CRUD의 개념**

| 구분 | 의미 |
|---|---|
| Create | 생성 |
| Read | 조회 |
| Update | 수정 |
| Delete | 삭제 |

**HTTP 요청 메서드**

| 메서드 | 기능 |
|---|---|
| GET | 데이터 조회 |
| POST | 데이터 생성 |
| PUT | 데이터 전체 수정 |
| PATCH | 데이터 일부 수정 |
| DELETE | 데이터 삭제 |

**HTTP 요청 구성 요소**

- Header: 요청과 관련된 부가정보
- Body: 서버에 전달할 데이터
- Body는 주로 JSON 형식으로 작성되며 Key와 Value로 구성된다.

프론트엔드에서는 React.js, Vue.js 등을 활용하며, 서버에 요청할 때 Header와 Body를 이용해 데이터를 전달할 수 있다.

**REST API URL 작성 규칙**

- 명사형 복수 형태 사용
  - 예: `users`
- 리소스의 계층 구조 표현
  - 예: `users/{userID}`

### 1.3 HTTP와 HTTPS

**HTTP(HyperText Transfer Protocol)**

클라이언트와 서버가 데이터를 주고받기 위한 통신 규약이다.

- 클라이언트와 서버 사이에서 요청과 응답을 전달한다.
- 일반 HTTP는 데이터를 암호화하지 않으므로 도청이나 변조 위험이 있다.

**HTTPS**

- HTTP에 보안 기능을 추가한 프로토콜이다.
- TLS를 이용해 데이터를 암호화한다.
- 금융 서비스, 쇼핑몰 등 민감한 정보를 주고받는 서비스에서 중요하다.

### 1.4 HTTP Response(응답)

서버가 클라이언트의 요청을 처리하고 결과를 반환하는 과정이다.

응답에도 Header와 Body가 있으며, 처리 결과를 나타내는 상태코드가 포함된다.

**HTTP 상태코드**

| 상태코드 범위 | 의미 |
|---|---|
| 2xx | 요청 성공 |
| 4xx | 클라이언트 요청 관련 오류 |
| 5xx | 서버 측 오류 |

- 200번대: 요청이 정상적으로 처리됨
- 400번대: 클라이언트 요청과 관련된 오류
- 500번대: 서버 내부에서 발생한 오류

### 1.5 API 명세 및 Endpoint

API 명세는 클라이언트와 서버가 데이터를 주고받는 방법을 정의한 것이다.

- Endpoint: 클라이언트가 서버의 특정 기능을 요청하는 접점
- 프론트엔드에서 백엔드로 요청을 보낼 때 사용한다.
- 요청 방식과 데이터 전달 구조를 정해 API를 연동한다.

## 2. 네트워크 구조 및 프론트엔드 (1-4강)

### 2.1 프론트엔드의 역할

프론트엔드는 사용자가 보는 웹페이지의 구조와 화면, 동적인 기능을 구현하는 영역이다.

주요 기술로 HTML, CSS, JavaScript가 있다.

### 2.2 HTML

HTML(HyperText Markup Language)은 웹페이지의 구조를 작성하는 마크업 언어이다.

- 웹페이지의 뼈대를 구성한다.
- 시맨틱 태그를 활용해 요소의 의미를 전달한다.
- 대표적인 시맨틱 태그: `<header>`, `<article>`

**HTML과 JSP**

- `.html`: HTML 문서를 작성하는 파일
- `.jsp`: 서버 측에서 동적으로 HTML을 생성할 수 있는 파일

### 2.3 CSS

CSS(Cascading Style Sheets)는 웹페이지의 스타일을 구성하는 기술이다.

- UI 스타일링
- 레이아웃 구성
- 반응형 디자인

**Media Query**

화면 크기 등의 조건에 따라 서로 다른 스타일을 적용하는 기능이다.

### 2.4 JavaScript

JavaScript는 웹페이지의 동적인 기능을 구현한다.

- 이벤트에 따른 동작 처리
- 사용자와의 상호작용 구현
- 화면 내용의 동적 변경

**Bootstrap**

웹페이지의 UI를 구성할 때 활용할 수 있으며, 다양한 스타일과 컴포넌트를 제공한다.

### 2.5 SPA(Single Page Application)

SPA는 하나의 페이지를 기반으로 화면을 동적으로 갱신하는 웹 애플리케이션 구조이다.

**동작 과정**

1. 처음 웹페이지를 로드한다.
2. HTML, CSS, JavaScript 파일을 기반으로 애플리케이션이 동작한다.
3. 서버에서 필요한 데이터를 전달받는다.
4. 페이지 전체를 다시 불러오지 않고 필요한 화면을 갱신한다.

**특징**

- 페이지 전체를 새로고침하지 않고 화면을 갱신할 수 있다.
- 서버로부터 데이터를 받아 동적으로 화면을 변경한다.
- 초기 로딩 속도가 느려질 수 있다.
- 필요에 따라 SSR(Server-Side Rendering)을 활용하여 일부 문제를 보완할 수 있다.

### 2.6 라이브러리와 프레임워크

**라이브러리(Library)**

- 재사용할 수 있는 코드와 기능의 모음
- 개발자가 필요한 기능을 직접 호출하여 사용

**프레임워크(Framework)**

- 애플리케이션의 구조와 실행 흐름을 제공
- 프레임워크가 전체 실행 흐름을 관리하면서 개발자가 작성한 코드를 호출

**React와 Vue.js**

- React: Facebook(Meta)에서 개발한 라이브러리로, 컴포넌트 기반 개발에 활용
- Vue.js: 컴포넌트와 템플릿을 활용하는 프레임워크

SPA 개발에서는 React의 JSX, Vue의 템플릿 등을 통해 HTML과 유사한 UI 구조를 JavaScript 기반 애플리케이션에서 구성할 수 있다.

## 3. API의 이해 및 개발 환경 실습 (1-5강)

### 3.1 개발 도구

**IDE 및 코드 편집 도구**

- Eclipse
- Visual Studio Code
- IntelliJ IDEA

VS Code를 이용해 웹 개발을 위한 코드와 프로젝트 파일을 관리하는 방법을 학습하였다.

### 3.2 웹 서버와 WAS

서버에는 웹 서버(Web Server)와 WAS(Web Application Server)가 있다.

- 웹 서버는 HTML, CSS, JavaScript 등의 정적 리소스를 제공할 수 있다.
- WAS는 애플리케이션을 실행하고 동적인 요청을 처리하는 역할을 한다.

### 3.3 VS Code 실습

**Live Server 설치**

- VS Code 확장 프로그램에서 Live Server 설치
- 로컬 환경에서 HTML 페이지를 실행하고 확인하는 데 활용

**HTML 파일 생성**

- HTML 파일 생성
- `html:5`를 이용하여 HTML 기본 구조 확인
- `<head>`와 `<body>` 영역의 역할 확인

**프로젝트 파일 관리**

- 페이지를 만들고 관련 파일을 폴더별로 관리하는 방법 학습

**Material Icon Theme 설치**

- VS Code 확장 프로그램에서 Material Icon Theme 설치
- 설치 후 파일 및 폴더의 아이콘이 변경되는 것을 확인
